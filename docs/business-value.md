# 商业价值与产业化验证

ChronosFix 的商业定位是 **带证明的软件变更基础设施 + 研发质量资产层**。它把事故证据、反事实实验、补丁验证、审批、PR 草案、审计和复盘连接起来，目标是降低高风险变更进入研发流程的信任成本。

> 证据边界：当前仓库证明的是合成场景下的工程闭环。尚无真实客户试点、生产 MTTR 对照、节省金额、付费转化或商业 ROI 数据；下述收益均为待验证假设。

## 为什么可能有采购价值

企业通常不会仅因 Agent 能生成代码就允许其进入生产。更可采购的交付物是：

- 根因判断可以回放，而不是只给结论；
- 失败变体、回滚和证据缺口不能被人工审批掩盖；
- 中高风险变更具名审批并留痕；
- PR 材料可直接供开发、SRE、发布和审计角色共同审查；
- 一次事故能够转成回归场景、证据模板和候选 Skill。

## 目标客户与待验证任务

| 客户 | 工作流痛点 | A-CFX 候选价值 | 需要验证 |
|---|---|---|---|
| 中大型研发组织 | Git、CI、日志、配置和工单割裂；复盘依赖专家 | 从事故证据形成可审查变更包 | MTTA、误归因、PR 材料耗时是否改善 |
| 云厂商/AIOps/DevOps 平台 | 能发现异常但难证明根因和补丁鲁棒性 | 作为 Incident-to-PR 治理插件 | 接口成本、运行稳定性、客户采用意愿 |
| 金融、政企、工业软件 | AI 变更需要审批、回滚和追责 | Evidence Passport 与 fail-closed RiskGate | 审计字段是否满足内部制度 |
| 开源维护团队 | Issue 到复现、验证、PR 说明成本高 | 本地可复现证据草案 | 是否减少维护者补充信息的往返 |

## 产品形态假设

- 团队版 SaaS：按项目数、月度回放次数或协作者规模计费；
- 企业私有化：部署在客户网络内，接内部 Git、CI、Trace 和审批；
- DevOps/云市场插件：作为 APM、CI/CD、配置中心或工单系统的增值模块；
- 审计模块：提供证据护照、具名审批、完整性摘要和回滚证明；
- 行业故障资产包：提供经过授权和脱敏的回放场景、测试模板与 Skill。

这些只是商业设计选项，当前没有收入或定价验证结果。

## 可防御资产假设

1. **反事实回放数据**：持续积累主因、干扰项、失败补丁和边界条件。
2. **Evidence Passport 契约**：把因果、验证、风险、回滚和完整性固定为跨工具接口。
3. **故障族回归集**：让一次事故转为可持续执行的质量资产。
4. **治理适配层**：通过 Tool/Skill 契约接 Git、CI、SLS、Nacos、Higress 等系统，而不把核心判断绑定单一厂商。

这些资产是否形成商业护城河，需要通过跨团队复用率、迁移成本和客户留存验证，不能仅由仓库规模推断。

## 商业实测设计

采用人工 baseline 与 A-CFX 同题对照，至少记录：

- 从告警到候选根因的时间；
- 从告警到可审查 PR 材料的时间；
- 主因命中与误归因；
- 审计字段完整度；
- 回滚演练成功率；
- 人工修改系统输出的比例；
- 试点团队是否愿意在第二个项目继续使用。

在完成真实试点前，PPT、README 和答辩中只描述“计划测量/目标指标”，不使用未经测量的节省百分比或金额。完整方法见 `docs/measurement-plan.md`。
