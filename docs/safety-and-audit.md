# 安全边界与审计

ChronosFix 的原则是：只读分析尽量自动化，任何可能影响环境的修复动作必须可审批、可回滚、可审计。

## 风险等级

| 等级 | 动作 | 策略 |
|---|---|---|
| L0 | 读取日志、Git、Trace、配置历史 | 自动执行 |
| L1 | 在隔离环境创建实验分支、重放测试、生成故障变体 | 自动执行 |
| L2 | 修改测试环境配置、生成修复分支、触发 CI | 需要策略检查 |
| L3 | 影响共享环境或生产的配置/发布动作 | 必须人工审批 |

当前 Demo 中，选中补丁风险分为 0.30，被归类为 medium，因此 `RiskGate` 要求人类确认。没有 `--approve` 参数时，流程会停在 `blocked-awaiting-human`。

## 证据护照门禁

补丁必须具备以下证据后，才允许进入发布审批：

- 需求声明：说明修复目标和不可违反的约束。
- 因果声明：说明为什么补丁针对主因而不是伪相关。
- 验证声明：说明补丁在故障基因变体中的表现。
- 风险声明：说明风险、成本和审批状态。
- 回滚声明：说明失败后如何恢复。
- 缺口声明：说明尚未覆盖或仍需人工判断的部分。

如果任一关键证据缺失，补丁只能作为建议，不得标记为可发布。

## 回滚策略

- 配置类修复：执行前保存旧值、配置快照和变更单号。
- 代码类修复：在独立分支提交，保留回滚 commit。
- 依赖类修复：保留 lockfile diff 和兼容性验证结果。
- 发布前要求：最差失败率低于阈值，P99 不超过阈值，Trace 完整，审批状态通过。

## 审计证据

- `trace.jsonl`：每次 Agent/Skill 调用的 span 记录。
- `proof-bundle.json`：结构化因果实验、故障变体、补丁竞赛、证据护照和指标。
- `proof-report.md`：面向 PR 或事故复盘的人类可读报告。

## 人类职责边界

ChronosFix 不替人类做最终高风险发布判断。它负责把证据准备好，让人类审批从“凭经验拍板”变成“基于因果、验证、风险和回滚证据决策”。
