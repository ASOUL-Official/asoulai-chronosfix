# AsoulAI ChronosFix（A-CFX）复赛 PPT 大纲

最终 PPT/PDF 共 22 页，沿用官方初赛 19 页模板的母版、色彩、页脚与内容框架，并按复赛“Demo 实现与工程验证”要求扩展。统一主线为：**事故证据 → 因果证明 → 故障族验证 → 补丁竞赛 → 三态门禁 → PR 证据护照 → 质量资产沉淀**。

## 逐页结构

1. **封面**：AsoulAI ChronosFix、方向三、A-CFX 品牌与复赛定位。
2. **项目定义**：把“会修复”升级为“带证据、可发布、可复用”。
3. **方案概述**：角色、证据、闭环和商业资产四个维度。
4. **结果摘要**：48.72%→6.25%、8 个故障变体、13 个证据声明、40 项测试。
5. **端到端闭环**：从事故 Issue 到 PR、run_id 与证据护照。
6. **输入输出契约**：同一事故输入为场景契约，输出为变更契约。
7. **章节页：AgentTeams 多 Agent 协同**。
8. **AgentTeams v1beta1**：1 Manager、8 Worker、1 Team、1 Human；11 份资源声明离线校验。
9. **角色与状态契约**：IncidentState、run/trace/parent 追踪与异常分支。
10. **因果治理与发布安全**：同干预冲突、无主因证据、验证不完整和具名审批。
11. **章节页：Skill 工程与云操作**。
12. **10 个 Skill 契约**：证据、因果、验证、资产复用和生命周期。
13. **官方 SLS Skill**：来源、只读权限、Worker 编排、失败处理与 dry-run 证据。
14. **技术架构与迁移边界**：当前实现、已验证契约、生产化目标；推荐组件不按数量堆叠。
15. **章节页：工程验证、安全与可审计**。
16. **运行证据链**：18 个真实计时 Span、checks、RiskGate、Run Manifest 与 SHA-256。
17. **Golden / Badcase 评测**：9/9 受支持诊断、1/1 冲突拒答、整体 10/12。
18. **失败案例与能力边界**：两个未建模 Badcase 与一个来源冲突场景全部公开。
19. **部署与复现**：README 入口、AgentTeams compatible transcript、契约校验、CI 和 GitHub Pages。
20. **商业价值**：团队试点版→企业集成版→平台生态版；价值指标以真实试点测量。
21. **开放与合规**：Apache-2.0、SBOM、第三方依赖披露、最小权限和分阶段接入。
22. **团队与提交物**：队名、作品名、代码仓库、Demo、方案材料和可验证证据入口。

## 统一口径

- `offline-validated`：确定性合成回放、本地测试和离线契约已验证。
- `dry-run`：真实接口契约或官方 Skill 已接入适配器，但没有宣称生产调用成功。
- `pending`：真实 AgentTeams Controller / Matrix 与推荐云组件仍为下一阶段迁移目标。
- 9/9 不是生产准确率；2 个未建模 Badcase 保留为已知漏诊。
- `intervention_effect_score` 是确定性干预效果分，不是统计学置信区间。
